# ERP 部署 SOP（v3.3）

> 目標：減少「其實程式沒壞，但看起來壞掉」的狀況（快取、網址、版本不同步）。  
> 適用：GitHub Pages 前端 + Apps Script 後端（/exec）。

---

### A. 什麼時候需要跑這份 SOP？

- 後端 Apps Script **重新部署**（/exec 變更或版本更新）
- 前端 **有改任何 JS/HTML/CSS**（尤其是核心檔：登入、路由、服務層、各模組）
- 緊急修補上線（要避免現場仍吃到舊碼）

---

### B. 部署步驟（照順序做）

---

### B0. 嚴格版最低門檻（強烈建議：每次上線都照做）

> 目標：把「明明修好了但現場還是壞」這種問題降到最低（快取、網址、版本不同步）。

#### ✅ 上線前（約 3 分鐘）

- **環境確認（DEV/PROD）**
  - `js/core/config.js` 必須同時維護：
    - `API_BASE_DEV`（測試 /exec）
    - `API_BASE_PROD`（正式 /exec）
  - 正式站若要強制保險：用 `?env=PROD` 開站驗證一次（避免誤連測試）。

- **快取版本（?v=）**
  - **只要你有改任何前端檔案**（JS/HTML/CSS），就必須在 `index.html` 更新該檔案的 `?v=YYYYMMDDx`
  - 原則：**改了什麼檔，就更新什麼檔的 ?v=**（不要只改一兩個、其餘漏掉）

#### ✅ 上線後（約 2–5 分鐘）

- **快速檢查（不用登入）**
  - 跑一次 `docs/erp-smoke-test.ps1`
  - 看到任何 `[FAIL]`：停止通知大家使用，先修正再上線

- **核心流程有動到才需要（測試環境優先）**
  - 若這次改到：登入/權限/收貨/出貨/加工/追溯/作廢等核心流程
  - 再跑一次全自動 E2E（依 `docs/ERP_上線自動檢查_使用說明_v3.3.md`）
  - 決策：E2E/閉環 **只在 DEV（測試）跑**；PROD（正式）不跑自動化，避免污染正式資料

#### 1) 取得新的後端部署網址（/exec）
- 從 Apps Script 部署後取得新的 Web App `/exec` 網址
- 建議先用瀏覽器打開一次，看到 `Unknown or missing action` 代表端點可連

#### 2) 更新前端連線設定（API_BASE）
- 更新 `js/core/config.js` 的 `API_BASE` 為新的 `/exec`
- 注意：若有多環境（正式/測試），務必確認你改的是要上線的那一份

#### 3) 更新關鍵腳本版本參數（避免 GitHub Pages 快取）
在 `index.html` 針對**有改到的檔案**，更新 `<script src="xxx.js?v=YYYYMMDDx">` 的版本字串。

- **原則**
  - 只要檔案內容有改，就要更新該檔案的 `?v=...`
  - 版本字串建議用日期＋尾碼（例如 `20260424a`），避免重複

- **建議優先（最常造成「看起來壞掉」）**
  - `js/core/service.js`（API 呼叫/錯誤處理）
  - `js/core/login.js`（登入/保持登入）
  - `js/router.js`（路由/權限導覽）
  - `js/core/utils.js`（共用邏輯）
  - 當次有改到的模組檔（例如 `js/products.js` 等）

#### 4) 上線前自我檢查（最少做 3 件事）
- `index.html` 的版本顯示是否正確（例如 v3.3 / Version 3.3）
- `API_BASE` 是否為你剛部署的 `/exec`
- `?v=` 是否已更新到你有改的檔案

#### 5) 推到 GitHub Pages（或你的前端佈署方式）
- 依你們既有方式上傳/發佈

---

### C. 使用者端「強制刷新」建議（避免仍吃到舊碼）

- Windows / Chrome：
  - 先按 `Ctrl + F5`（強制重新載入）
  - 若仍異常：開無痕視窗測試
  - 最後手段：清除該網站的快取資料

> 提醒：只要你有更新 `?v=`，多數情況不用要求使用者清快取。

---

### D. 上線後驗證（最小驗證清單）

> 目標：5 分鐘內確認「核心流程沒壞」。

- **登入**
  - 可正常登入（含保持登入/重新整理不會一直跳回登入）
  - 右上角可看到目前身分

- **主檔**
  - 產品/供應商/客戶任一頁：列表可載入、可建立/更新（依權限）

- **收貨 → 批次 → 出貨 → 追溯（最短閉環）**
  - 收貨頁可開啟與載入
  - 批次列表可載入
  - 出貨頁可開啟與載入
  - 追溯頁可查到資料（至少能正常顯示，不會整頁卡住）

- **操作紀錄**
  - Logs（若有權限）可開啟、可查詢

---

### E. 常見問題與排查方向（只寫最常見 3 種）

- **一直跳「權限不足 / Permission denied」**
  - 先確認：是不是吃到舊版前端（`?v=` 沒更新）  
  - 再確認：該帳號是否真的有被分配對應功能

- **一直跳「需要重新登入 / session 過期」**
- 先確認 `API_BASE` 是否指到正確 `/exec`
  - 再確認是否有混用不同環境（測試/正式交錯）

- **修好了但使用者仍看到舊行為**
  - 幾乎都是快取：確認你有更新該檔案的 `?v=`
