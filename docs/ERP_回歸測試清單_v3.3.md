# ERP 回歸測試清單（v3.3｜每次改版都照跑）

> 目的：避免「修 A 壞 B」沒發現；用最短路徑確認核心流程可用。  
> 原則：只驗「能不能用」與「狀態/權限/快取」三大類，不追求把所有功能點完。

---

## A. 使用方式（30 秒）

- **DEV（測試）**：先跑自動檢查（快速檢查 / E2E），再用本清單做人工補漏
- **PROD（正式）**：不跑自動化，只跑本清單的「最小人工驗證」
- 每次改版，至少勾完 **A～D**（約 5–10 分鐘）

---

## B. 前置確認（部署與快取）

- [ ] `index.html` 顯示版本為 **v3.3 / Version 3.3**
- [ ] 本次有改到的前端檔案，`index.html` 對應 `<script src="...?...">` 的 **`?v=` 已更新**
- [ ] `API_BASE` 指向正確環境（DEV/PROD）
  - DEV：可用 `?env=DEV` 強制開站確認
  - PROD：可用 `?env=PROD` 強制開站確認

---

## C. 登入與權限（最容易壞、也最容易誤判快取）

- [ ] 可正常登入（含「登入中」提示有出現且不會卡住）
- [ ] 重新整理頁面後，不會一直跳回登入（保持登入/續期正常）
- [ ] 右上角顯示的身分資訊正確（角色中文 - ID）
- [ ] 權限符合預期
  - [ ] 有權限的模組：側邊欄看得到、點得進去
  - [ ] 沒權限的模組：側邊欄看不到、直接打網址也進不去（會被擋）

---

## D. 主檔（挑 1–2 個最常用頁面）

> 建議優先：產品、倉庫（最常被交易引用）

- [ ] 主檔列表可載入（不會整頁卡住/無限轉）
- [ ] 主檔新增/更新可成功（依你的角色權限）
- [ ] 主檔狀態（ACTIVE/INACTIVE）限制符合規則（僅 CEO/GA/ADMIN 可改）

---

## E. 核心交易最短閉環（收貨 → 批次 → 出貨 → 追溯）

- [ ] 以「最短閉環」驗證核心交易可用：收貨 → 批次 → 出貨 → 追溯
- [ ] 若本次改動涉及交易一致性（bundle/命令/防重/硬擋），請依下方 **I-1** 逐項驗證（此處不重複列細節）

---

## F. 作廢/取消（高風險但最常出事）

> 只要本次有動到交易流程、權限、或 service/router，建議至少測其中一個。

- [ ] 作廢/取消後，狀態與庫存回到一致（不會留半套）
- [ ] 若本次改動涉及交易一致性，請依下方 **I-1** 驗證收貨/出貨作廢（含 idempotency 與反沖一致性）

---

## G. Sheet 連結（維運入口）

- [ ] 任一頁點 `Sheet` 能開到對應分頁（不是全部都第一頁）
- [ ] 正式站點 `Sheet` 不會開到測試表（DEV/PROD 不串台）

## H. Logs（可追溯）

- [ ] Logs 頁可開啟、可查詢（有權限者）
- [ ] 新增/更新/過帳等操作後，能查到紀錄（至少抽 1 筆驗證）

## I. 交易一致性（Phase 1–3 加強回歸｜本次改造重點）

> 這一章是「寫給跑回歸的人」的操作版清單：照著點就能跑完，不需要懂 action 名稱。  
> 提醒：若本次有改到後端（Apps Script），請先重新部署 DEV/PROD；前端請 Ctrl+F5 以避免快取。

### I-0) 跑回歸時要回報哪些資訊（避免來回問）

每一步若失敗，請回報三件事（貼文字即可）：
- **你在哪個頁面/按了哪個按鈕**
- **畫面跳出的 Toast 文字**（完整一句）
- **該單號/批號/出貨單 ID**（例如 GR/IR/LOT/MV/SO/SHIPMENT）

### I-1) Phase 1：收貨/出貨/庫存操作（高風險優先）

#### (1) Receive（收貨入庫）

目標：確認「產生批次」與「作廢」會把 Lot/庫存/上游狀態一次同步好，不會留半套。  
（後端 action：post/cancel goods_receipt/import_receipt bundle）

- [ ] 進入 `Receive`，先選 **PO** 或 **進口報單**（擇一先跑最常用的）
- [ ] 選一張「還有可收數量」的來源單，任選一列輸入本次收貨量（>0），並選倉別
- [ ] 按 **「產生批次」**
  - [ ] 通過判斷：出現成功提示，且可在 `Lots` / `Movements` 搜到對應的收貨單 ID（有 IN 異動/有新 Lot）
- [ ] 回到 `Receive`，對剛剛那張收貨單按 **「作廢」**
  - [ ] 通過判斷：出現作廢完成提示，`Movements` 有反沖（ADJUST），Lot 狀態合理（VOID/REJECTED 或依你們規則）
- [ ] 回到來源單（PO/報單）確認狀態回寫合理（OPEN/PARTIAL/CLOSED 的變化符合預期）

#### (2) Shipping（出貨管理）

目標：確認「建立並過帳出貨」會扣庫並回寫 SO；「作廢」會反沖並回寫 SO。  
（後端 action：post/cancel shipment bundle；備註為 remark-only command）

- [ ] 進入 `Shipment 出貨管理`
- [ ] 建一張出貨單（至少 1 筆明細），按 **「建立並過帳出貨（扣庫）」**
  - [ ] 通過判斷：顯示成功提示；`Movements` 可查到 SHIP_OUT；回到該 SO 狀態/已出數量合理
- [ ] 對這張出貨單按 **「作廢出貨單（反沖庫存）」**
  - [ ] 通過判斷：顯示作廢成功；`Movements` 有反沖（ADJUST）；SO 的 shipped_qty/status 回復合理
- [ ] 備註測試（至少擇一）
  - [ ] 主檔：修改主檔備註 → 按 **「儲存備註」** → 成功
  - [ ] 明細：點選一筆明細 → 修改備註 → 按 **「儲存備註」** → 成功（POSTED 才允許）

#### (3) Merge / Split / Transfer（合批 / 拆批 / 轉倉）

目標：確認這三個「特殊庫存作業」都走整包流程，不會寫一半。  
（後端 action：post_merge_bundle / post_split_bundle / post_transfer_bundle）

- [ ] 合批：用 2 個來源 Lot 合成 1 個新 Lot
  - [ ] 通過判斷：新 Lot 出現；來源 Lot 可用量下降；`Movements` 有 IN/OUT；`Trace` 追得到 lot_relation
- [ ] 拆批：用 1 個來源 Lot 拆出 1+ 個新 Lot
  - [ ] 通過判斷：來源 Lot 扣庫；新 Lot 出現；`Movements` 有 OUT/IN；`Trace` 追得到 lot_relation
- [ ] 轉倉：把某 Lot 的數量轉到另一個倉（會產生新 Lot）
  - [ ] 通過判斷：新 Lot 出現且倉別正確；`Movements` 有 OUT/IN；原 Lot 可用量下降
- [ ] 失敗保護：故意輸入超過可用量，應被擋下，且不應留下任何新 Lot 或半套 movements

### I-2) Phase 2：半交易硬擋（避免 API 側門）

#### (1) PO（採購）— 有收貨後

目標：一旦已收貨，PO 結構欄位不允許再改，只允許備註（避免追溯不一致）。

- [ ] 找一張「已收貨」的 PO（存在未作廢收貨單）
- [ ] 嘗試改主檔欄位（例如：供應商/日期等）→ 應被擋下（Toast 會提示僅可改備註）
- [ ] 嘗試改明細的品項/數量/單位 → 應被擋下
- [ ] 嘗試新增明細 → 應被擋下
- [ ] 但 **儲存備註仍應成功**（主檔與明細備註）

#### (2) Import Doc（進口報單）— 有收貨後

目標：一旦已收貨，報單結構欄位不允許再改，只允許備註。

- [ ] 找一張「已收貨」的報單（存在未作廢收貨單）
- [ ] 嘗試改主檔欄位（例如：單號/日期/供應商等）→ 應被擋下
- [ ] 嘗試改明細的品項/申報量/單位 → 應被擋下
- [ ] 嘗試新增明細 → 應被擋下
- [ ] 但 **儲存備註仍應成功**（主檔與明細備註）

#### (3) SO（銷售）— 有出貨追溯後

目標：一旦已有出貨追溯（已有出貨明細），SO 結構欄位不允許再改，只允許備註。

- [ ] 找一張「已有出貨」的 SO（能在出貨明細查到 shipment_item）
- [ ] 嘗試改主檔欄位（例如：客戶/日期等）→ 應被擋下
- [ ] 嘗試改明細的品項/數量/單價 → 應被擋下
- [ ] 嘗試新增明細 → 應被擋下
- [ ] 但 **儲存備註仍應成功**（主檔與明細備註）

#### (4) 終態（CANCELLED/CLOSED/POSTED/SHIPPED）
- [ ] 找一張終態單據（已作廢/已關閉/已過帳/已出畢）
- [ ] 嘗試改結構欄位 → 應被擋下
- [ ] 嘗試新增明細 → 應被擋下
- [ ] 但 **儲存備註仍應成功**（依畫面允許的範圍）

### I-3) Phase 3：UI 體感一致化
- [ ] 各模組點選明細列時，提示句型一致：`已帶入明細（僅改備註…；改數量先…）`
- [ ] 各模組上方狀態列句型一致：`模組：狀態 · 提示`
